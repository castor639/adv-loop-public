# Domain profiles

The ADV Loop engine validates **structure** — presence, hashes, counts, set membership,
ordering — and never interprets domain content. These profiles prove it by construction:
the same machinery, instantiated in four deliberately dissimilar fields. Each profile
maps every generic concept the loop schedules and enforces onto that field's ordinary
practice. Nothing in `src/` knows which profile is in play (the test suite's neutrality
lint keeps it that way).

| Generic concept | One field-free sentence |
|---|---|
| **criterion** | An observable outcome the task is not done without. |
| **kill test** (seed) | The fastest concrete check that would destroy the idea. |
| **control** | An object a correct mechanism must *not* certify. |
| **basin** | The conceptual family an approach belongs to; closed after repeated confirmed failure, re-entered only with a stated representation shift. |
| **asset** | A reusable result, technique, tool, or source with a locator. |
| **combine move** | An experiment joining two assets never previously put together. |
| **survey move** | An experiment whose product is imported knowledge, registered as assets. |
| **barrier** | A named obstruction with an exact statement; probed by bounding it, taking its dual, or shifting representation. |
| **wish** | A dated, testable hope: "if X becomes available, route R reopens." |
| **replicate move** | Re-running a validated result to see whether it survives. |
| **lens** | The single assigned angle of a review: correctness, novelty, proves-too-much, or simplification. |
| **lesson** | A candidate cause of repeated failure, with a test that would discriminate it. |
| **intake drop** (4.0) | An unsorted bundle of work, partitioned into isolated task workspaces before anything runs. |
| **payload** (4.0) | The dropped source material a task's evidence points into; never a projection of the event log. |
| **sandbox** (4.0) | A declared, pinned execution environment; the kernel runs only argv lists the operator declared. |
| **checker hook** (4.0) | A registered external validator whose accept/reject verdict is embedded as attested evidence. |
| **formalization rank** (4.0) | How strong a field's strongest honest check is, from a sourced citation up to a proof-kernel acceptance; a criterion may demand a minimum. |
| **overlay** (4.0) | A reviewed, adopted amendment to one workspace's contract that may only add or tighten. |
